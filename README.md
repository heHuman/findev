# Findev Markets: realtime fintech dashboard

An Angular app that shows live metrics for fictional financial instruments. The market data is generated by a WebAssembly library (written in AssemblyScript) running inside a Web Worker.

- **Live demo:** https://hehuman.github.io/findev/
- **Repository:** https://github.com/heHuman/findev

## Features

- **Dashboard:** one row per instrument with last traded price, bid–ask spread, cumulative volume, VWAP and order-book imbalance. Values update live; unavailable values show `—`.
- **Pause / Resume:** pausing stops generation in the worker; resuming continues with the same totals and doesn't make up the paused time.
- **Producer status:** state, run number, total updates and batches, plus an error message with **Retry** if the producer fails to start.
- **Settings:** a validated form for instrument count, updates per batch and batch interval. **Apply** starts a new run with fresh totals, even when paused. Navigating between pages keeps the current run and its state.

## Getting started

**Prerequisites:** Node.js **24.22** or newer within 24.x (see [.nvmrc](.nvmrc)); Angular 22 needs at least 24.15. npm 11 comes with it.

```bash
npm install
```

Everything runs from the repository root. The dashboard's `start`, `build` and `test` scripts build the Wasm first, so there's no separate step.

| Task                                                       | Command                              |
| ---------------------------------------------------------- | ------------------------------------ |
| Run the app (http://localhost:4200)                        | `npm start -w @findev/dashboard`     |
| Production build (`apps/dashboard/dist/dashboard/browser`) | `npm run build -w @findev/dashboard` |
| All tests (Wasm library + app)                             | `npm test`                           |
| Wasm library tests only                                    | `npm test -w @findev/producer`       |
| App tests only                                             | `npm test -w @findev/dashboard`      |
| Build only the Wasm                                        | `npm run build:wasm`                 |

All tests are unit tests (Vitest); there are no end-to-end tests.

## Architecture

```
 Angular main thread                     Web Worker                        Wasm (AssemblyScript)
 ┌──────────────────────┐  start/pause/  ┌───────────────────────────┐    ┌──────────────────────┐
 │ ProducerService      │  resume/dispose│ ProducerController        │    │ producer.wasm        │
 │  (one per app)       │ ─────────────► │  setInterval per batch    │ ─► │  seeded RNG          │
 │  status, metrics,    │                │  running totals per       │    │  per-instrument      │
 │  counters (signals)  │ ◄───────────── │  instrument (Float64Array)│ ◄─ │  random-walk prices  │
 └──────────────────────┘  ready/status/ └───────────────────────────┘    └──────────────────────┘
        │                 snapshot/error      Int32Array view over Wasm memory
        ▼
 Dashboard (virtual-scrolled table), Settings form, toolbar status badge
```

- **Wasm** generates _market updates_, not metrics: each update is one trade plus the current bid/ask and book quantities, as 7 integers (cents and units). Randomness and price evolution run inside Wasm; JS only passes a seed. Per-instrument state carries over between batches, and every update is valid by construction: `price > 0`, `bid < ask`, the trade price equals the bid or the ask, and quantities are in range.
- **The worker** owns the Wasm instance and the batch timer. It adds **every** trade into cumulative totals (last price, latest quotes, volume, Σ price × qty) and never stores the event history. After each batch it derives the five metrics and posts a snapshot.
- **The main thread** sends commands and stores the latest snapshot in signals. Every event carries a **run id**; events from an earlier run are ignored, so a previous run can never overwrite the new one. Apply resets the rows and counters immediately, before the worker answers.
- **Metrics:**
  - spread = ask − bid
  - VWAP = Σ(price × qty) / Σ qty
  - imbalance = (bidQty − askQty) / (bidQty + askQty)

  A zero denominator gives "unavailable". Prices stay in integer cents and are only rounded for display.

## Key decisions

- **AssemblyScript for the Wasm library:** TypeScript syntax, npm tooling and a ~2 KB module. Its tests run against the compiled `.wasm`.
- **Totals live in the worker:** generation and accumulation never block the UI, and the UI can refresh less often than data is produced without losing trades.
- **Snapshots are plain objects** (structured clone). That's well under 0.1 ms on the main thread at the current limit. A measured alternative for thousands of instruments is to transfer a `Float64Array` and turn only the visible rows into objects, which keeps the main-thread cost flat.
- **The table uses CDK virtual scrolling** with a fixed row height, so only the visible rows (plus a buffer) are in the DOM, whatever the instrument count.
- **The Wasm library has no instrument cap.** Memory grows on `init` when needed, and running out returns an error instead of crashing. The app limits the count in its settings (`apps/dashboard/src/app/settings/producer-settings.ts`).
- **Zoneless Angular with signals and OnPush:** one render per snapshot, coalesced by Angular's scheduler.

## Deployment

Every push to `main` runs [.github/workflows/deploy.yml](.github/workflows/deploy.yml):

1. `npm ci`
2. `npm test`
3. A production build with the GitHub Pages base path
4. `404.html` copied from `index.html`, so deep links such as `/findev/settings` work
5. Deployment to GitHub Pages

Pull requests run the tests and build without deploying.

One-time setup on GitHub: **Settings → Pages → Source: GitHub Actions**.

To build with a sub-path locally from Git Bash, prefix the command with `MSYS_NO_PATHCONV=1`. Otherwise Git Bash rewrites `/findev/` into a Windows path:

```bash
MSYS_NO_PATHCONV=1 npm run build -w @findev/dashboard -- --base-href /findev/
```
